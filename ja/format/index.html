01構成

作るのは、思っているより簡単です。

.swaylume はただのフォルダです。macOS がバンドルとして登録するので、Finder では 1 つのファイルに見えます。中身は「これが何か」を書いたマニフェストと、素材を入れた content/ だけ。ビルド工程も SDK もアカウント登録も要りません。

マニフェスト 1 つと、フォルダ 1 つ。

preview.jpg は省略できます。省略すると Swaylume が素材から表紙のコマを選びます（動画では黒画面を避け、明るさの分散がいちばん大きいコマを採用）。content/ の中身は type によって決まります。

MyWallpaper.swaylume/ ├── manifest.json // 必需 / required ├── preview.jpg // 可选 / optional └── content/ // 必需 / required ├── video.mp4 // type == "video" ├── index.html + assets/ // type == "web" ├── image.png // type == "image" └── layers.json + *.png // type == "layered"
02マニフェスト

manifest.json に書くこと。

必須は 4 つ、残りは任意です。読み込み側は知らないフィールドを無視するので、余分に書いてもエラーにはなりません。

{ "formatVersion": 1, "title": "Neon City", "author": "someone", "type": "video", "entry": "video.mp4", "preview": "preview.jpg", "fillMode": "fill", "muted": true }
フィールド必須説明
formatVersion必須現在は常に 1。対応より新しい版のパッケージは読み込みを拒否します
title必須表示名
type必須video / web / image / layered
entry必須エントリファイル（content/ からの相対パス）
authorクレジットライブラリと属性パネルに表示されます
previewプレビュー画像（パッケージ直下からの相対パス）
fillModefill / fit / stretch / center既定は fill
muted既定は true音声のある素材にのみ意味があります
propertiesユーザーが調整できるパラメータweb 型のみ。次節を参照
sourceNote出所メモ表示専用で、動作には影響しません
03パラメータ

属性パネルから調整できるようにする。

web 壁紙だけの機能です。マニフェストに宣言したものが、そのまま Swaylume の属性パネルに現れます —— スイッチ、スライダー、色、ファイル選択、テキスト入力。ドラッグした瞬間にページへ届き、再読み込みは不要です。

"properties": { "speed": { "number": { "_0": { "value": 0.35, "min": 0, "max": 1 } } }, "showtext": { "bool": { "_0": true } }, "greeting": { "text": { "_0": "hello" } }, "schemecolor": { "color": { "_0": "0.2 0.6 1" } }, "background": { "file": { "_0": { "fileType": "image" } } } }
case_0 の型パネルでの見え方
boolBoolスイッチ
number{ value, min, max }スライダー
textStringテキスト入力
colorString、"r g b"（0…1 の浮動小数 3 つ）カラーピッカー
file{ fileType }ファイル選択
directory{ fileType }フォルダ選択
number の _0 は数値ではなくオブジェクトです。スライダーは範囲が分からないと描けません。Wallpaper Engine のスライダーは実際に 0…1、0…100、0…359、0…1000 とさまざまで、範囲がないと属性パネルは推測するしかなく、ドラッグの手応えが全部ずれます。
file / directory に書くのは fileType だけです。ユーザーが素材を選ぶと、アプリが bookmark と displayName を追記します。これは security-scoped ブックマークで、ローカルのライブラリにのみ存在し、パッケージ形式の一部ではありません。書き出し時には取り除かれます（フォルダ名を含むため、外に出すべきではありません）。
Wallpaper Engine 向けに書いたページは、ほぼそのまま動きます。これらの値は { name: { value, type } } の形で wallpaperPropertyListener.applyUserProperties に渡され、Wallpaper Engine の約束と同じです。プロパティ監視、ランダムなファイル取得、音声コールバックは互換レイヤーが補います。
04レイヤー

2.5D 視差 —— 数枚の画像に、それぞれ奥行きを。

type を layered にし、content/ に layers.json と切り出した画像を置きます。depth は 0…1：0 がいちばん遠くほとんど動かず、1 がいちばん手前でポインタに最も追随します。層どうしの相対的な動きが奥行き感の正体です。動画のデコードがないので消費電力はごくわずかです。

// レイヤー壁紙のフォーマット定義は、これだけ { "layers": [ { "image": "sky.png", "depth": 0.0 }, // 最も遠く、ほとんど動かない { "image": "hills.png", "depth": 0.45 }, { "image": "tree.png", "depth": 1.0 } // 最も近く、最も大きく動く ] }
05取り決め

この形式の変わり方。

formatVersion が上がるのは破壊的変更のときだけです。つまり 今日作ったパッケージが、明日フィールドを足したせいで動かなくなることはありません。

追加フィールドは常に任意。読み込み側は知らないフィールドを無視しなければならず、エラーにしてはいけません。これは推奨ではなく厳格な規則です。
formatVersion は破壊的変更でのみ上がる。フィールドの追加は破壊的ではありません。仮に上がっても、古いパッケージは読めます（新機能が使えないだけ）。
旧拡張子も引き続き認識。改名前に .livewall で書き出したパッケージも中身は同じ v1 形式で、Finder の関連付けも読み込みも従来どおり。新規の書き出しだけが .swaylume になります。
書き手と読み手は同じ契約。変換ツールとアプリの読み込み処理は同時に変える必要があります。片方だけ先に進めると、書き出したパッケージを自分で読めなくなります。
投稿の前に、手元で一度動かしてください。.swaylume を Swaylume にドラッグして、ちゃんと再生され、属性パネルのパラメータが意図どおりに効くところまで確認して初めて完成です。カタログ側の CI は構造とチェックサムを再検証しますが、「見た目が正しいか」は検証できません —— それはあなたにしか分かりません。
