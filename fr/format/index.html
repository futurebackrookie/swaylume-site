    01Structure

    En créer un est plus simple que vous ne croyez.

    Un .swaylume n’est qu’un dossier — macOS l’enregistre comme bundle, le Finder affiche donc un seul fichier. Dedans : un manifeste qui dit ce que c’est, et un content/ avec la matière. C’est tout. Aucune étape de compilation, aucun SDK, aucun compte à créer.

    Un manifeste, un dossier.

    preview.jpg est facultatif — sans lui, Swaylume choisit lui-même une image de couverture dans la matière (pour la vidéo il évite les images noires et prend celle dont la variance de luminosité est la plus forte). Le contenu de content/ dépend de type.

    MyWallpaper.swaylume/ ├── manifest.json // 必需 / required ├── preview.jpg // 可选 / optional └── content/ // 必需 / required ├── video.mp4 // type == "video" ├── index.html + assets/ // type == "web" ├── image.png // type == "image" └── layers.json + *.png // type == "layered"
    02Manifeste

    Ce que contient manifest.json.

    Quatre champs requis, le reste est facultatif. Le lecteur ignore les champs qu’il ne connaît pas : un extra n’est jamais une erreur.

    { "formatVersion": 1, "title": "Neon City", "author": "someone", "type": "video", "entry": "video.mp4", "preview": "preview.jpg", "fillMode": "fill", "muted": true }
    ChampRequisRemarques
    formatVersionRequisToujours 1 pour l’instant. L’app refuse un paquet plus récent qu’elle
    titleRequisNom affiché
    typeRequisvideo / web / image / layered
    entryRequisFichier d’entrée, relatif à content/
    authorCréditAffiché dans la bibliothèque et l’inspecteur
    previewImage d’aperçu, relative à la racine du paquet
    fillModefill / fit / stretch / centerPar défaut : fill
    mutedPar défaut trueUtile seulement si la matière a du son
    propertiesParamètres réglablesUniquement pour les fonds web — voir plus bas
    sourceNoteNote de provenanceAffichage seul, sans effet sur la logique
    03Paramètres

    Laissez régler votre fond depuis l’inspecteur.

    Fonds web uniquement. Ce que vous déclarez dans le manifeste est exactement ce qui apparaît dans l’inspecteur de Swaylume — interrupteurs, curseurs, couleurs, sélecteurs de fichier, champs texte. Les valeurs atteignent la page pendant le glissement, sans rechargement.

    "properties": { "speed": { "number": { "_0": { "value": 0.35, "min": 0, "max": 1 } } }, "showtext": { "bool": { "_0": true } }, "greeting": { "text": { "_0": "hello" } }, "schemecolor": { "color": { "_0": "0.2 0.6 1" } }, "background": { "file": { "_0": { "fileType": "image" } } } }
    caseType de _0Rendu dans l’inspecteur
    boolBoolInterrupteur
    number{ value, min, max }Curseur
    textStringChamp texte
    colorString, "r g b" — trois flottants 0…1Sélecteur de couleur
    file{ fileType }Sélecteur de fichier
    directory{ fileType }Sélecteur de dossier
    Pour number, _0 est un objet, pas un nombre nu. Un curseur ne se dessine pas sans sa plage — les curseurs de Wallpaper Engine se rencontrent en 0…1, 0…100, 0…359, 0…1000. Sans plage, l’inspecteur doit deviner, et chaque glissement tombe à côté.
    Pour file / directory, vous n’écrivez que fileType. Dès que l’utilisateur choisit quelque chose dans Swaylume, l’app y ajoute bookmark et displayName — un signet à portée de sécurité, présent uniquement dans la bibliothèque locale, qui ne fait pas partie du format et que l’export retire (il transporte vos noms de dossiers).
    Les pages écrites pour Wallpaper Engine fonctionnent presque telles quelles. Ces valeurs parviennent à la page sous la forme { name: { value, type } } via wallpaperPropertyListener.applyUserProperties, conformément à la convention de Wallpaper Engine. Écoute des propriétés, tirage aléatoire de fichiers et rappels audio sont fournis par la couche de compatibilité.
    04Calques

    Parallaxe 2.5D : quelques images, chacune avec sa profondeur.

    Mettez type à layered et placez un layers.json et vos images détourées dans content/. depth va de 0 à 1 : 0 est le plus loin et bouge à peine, 1 est le plus près et suit le curseur le plus. C’est le mouvement relatif entre les calques qui crée la profondeur — sans décodage vidéo, pour une consommation quasi nulle.

    // Toute la définition du format d’un fond d’écran en calques { "layers": [ { "image": "sky.png", "depth": 0.0 }, // le plus loin, bouge à peine { "image": "hills.png", "depth": 0.45 }, { "image": "tree.png", "depth": 1.0 } // le plus près, bouge le plus ] }
    05Engagement

    Comment ce format a le droit d’évoluer.

    Seule une rupture touche à formatVersion. Autrement dit : un paquet créé aujourd’hui ne cessera pas de fonctionner parce que nous ajoutons un champ demain.

    Les nouveaux champs sont toujours facultatifs.Le lecteur doit ignorer un champ inconnu plutôt qu’échouer. C’est une règle stricte, pas un conseil.
    formatVersion ne monte qu’en cas de rupture.Ajouter un champ ne rompt rien. Si elle montait, les anciens paquets se chargeraient encore — sans la nouveauté.
    L’ancienne extension reste reconnue.Les paquets exportés en .livewall avant le changement de nom contiennent le même format v1 ; association Finder et import fonctionnent comme avant. Seuls les nouveaux exports sont en .swaylume.
    L’écrivain et le lecteur ne font qu’un contrat.Le convertisseur et le chemin d’import de l’app changent ensemble. Laisser un côté prendre de l’avance, c’est exporter des paquets qu’on ne sait plus relire.
    Faites-le tourner chez vous avant de soumettre. Glissez le .swaylume directement dans Swaylume : il doit se lire, et chaque paramètre de l’inspecteur doit faire ce que vous vouliez. La CI du dépôt du catalogue revérifie structure et sommes de contrôle, mais elle ne peut pas vérifier si le rendu est juste — vous seul le pouvez.
