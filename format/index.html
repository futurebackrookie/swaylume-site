01包的结构

做一张壁纸，比你以为的简单。

一个 .swaylume 就是个普通目录 —— macOS 把它注册成 bundle，所以在访达里看着像单个文件。里面一份清单交代这是什么，一个 content/ 放素材，就这些。没有编译步骤，没有 SDK，不用注册账号。

一份清单，一个目录。

preview.jpg 可以不给 —— 不给的话 Swaylume 自己从素材里挑一帧当封面（视频会跳过黑场，按亮度方差挑最有内容的一张）。content/ 里放什么取决于 type。

MyWallpaper.swaylume/ ├── manifest.json // 必需 / required ├── preview.jpg // 可选 / optional └── content/ // 必需 / required ├── video.mp4 // type == "video" ├── index.html + assets/ // type == "web" ├── image.png // type == "image" └── layers.json + *.png // type == "layered"
02清单

manifest.json 里有什么。

四个必填，其余全可选。读端遇到不认识的字段会忽略，所以你多写了也不会报错。

{ "formatVersion": 1, "title": "Neon City", "author": "someone", "type": "video", "entry": "video.mp4", "preview": "preview.jpg", "fillMode": "fill", "muted": true }
字段必需说明
formatVersion必需目前恒为 1。app 会拒绝加载版本号高于自己支持的包
title必需显示名
type必需video / web / image / layered
entry必需入口文件，相对 content/
author作者署名会显示在库和属性面板里
preview预览图，相对包根目录
fillModefill / fit / stretch / center缺省 fill
muted缺省 true只对有声音的素材有意义
properties用户可调的参数只有 web 类型用得上，见下一节
sourceNote来源说明只用于展示，不参与任何逻辑
03可调参数

让用户能在属性面板里调你的壁纸。

只有网页壁纸用得上。你在清单里声明什么，Swaylume 的属性面板里就出现什么 —— 开关、滑块、颜色、选图、文本框。用户拖动的瞬间就下发给页面，不用重载。

"properties": { "speed": { "number": { "_0": { "value": 0.35, "min": 0, "max": 1 } } }, "showtext": { "bool": { "_0": true } }, "greeting": { "text": { "_0": "hello" } }, "schemecolor": { "color": { "_0": "0.2 0.6 1" } }, "background": { "file": { "_0": { "fileType": "image" } } } }
case_0 的类型面板里长什么样
boolBool开关
number{ value, min, max }滑块
textString文本框
colorString，"r g b" 三个 0…1 浮点取色器
file{ fileType }选文件按钮
directory{ fileType }选目录按钮
number 的 _0 是个对象，不是裸数字。滑块得知道量程才画得出来 —— 实测 Wallpaper Engine 的滑块有 0…1、0…100、0…359、0…1000 各种量程，不带范围的话属性面板只能瞎猜一个区间，拖起来全不对。
file / directory 你只写 fileType。用户在 Swaylume 里选好素材之后，app 会往里补 bookmark 和 displayName —— 那是 security-scoped 书签，只存在于本机的库文件里，不属于包格式的一部分，导出时会被剥掉（它带着你的目录名，泄漏出去不合适）。
为 Wallpaper Engine 写过的页面基本不用改。这些值最终以 { name: { value, type } } 的形状交给页面的 wallpaperPropertyListener.applyUserProperties，和 Wallpaper Engine 的约定一致。属性监听、随机取文件、音频回调都由兼容层补齐。
04分层壁纸

2.5D 视差：几张图，各带一个景深。

type 写 layered，content/ 里放一个 layers.json 和几张切好的图。depth 是 0…1：0 最远、几乎不动，1 最近、跟着鼠标动得最多。层间的相对运动就是景深感的来源 —— 没有视频解码，几乎不耗电。

// 分层壁纸的全部格式定义，就这么多 { "layers": [ { "image": "sky.png", "depth": 0.0 }, // 最远，几乎不动 { "image": "hills.png", "depth": 0.45 }, { "image": "tree.png", "depth": 1.0 } // 最近，动得最多 ] }
05约定与投稿

这份格式会怎么变。

只有破坏性变更才会动 formatVersion。换句话说：你今天做的包，不会因为我们明天加了个字段就失效。

新增字段一律可选。读端遇到不认识的字段必须忽略，不能报错 —— 这条是硬约束，不是建议。
formatVersion 只在破坏性变更时递增。加字段不算破坏性。真要递增，旧包会继续被读，只是新特性用不上。
旧扩展名仍然认。改名之前导出的 .livewall 包内部就是同一份 v1 格式，访达关联和导入都照常；只是新导出一律用 .swaylume。
写端和读端是同一份契约。转换工具和 app 的导入逻辑必须同步改，不允许一边先行 —— 一边先行的结果就是导出的包自己读不回来。
先在本机跑一遍再投稿。把 .swaylume 直接拖进 Swaylume，能正常播放、属性面板里的参数都对得上，才算做完。目录仓库的 CI 会再验一次结构和校验和，但它验不了「看起来对不对」—— 那只有你自己能验。
